## An AI is a brain in a jar

It is very smart, and it is completely stuck.

It can *think* about your files. It can't *open* them. It can *talk* about
rolling dice. It can't actually roll one — ask it for a random number and it
will pick 7 far more often than chance allows, because it is pattern-matching,
not rolling.

Your code is the opposite problem. It has hands and no idea what you want.

## The fix is a list taped to a box

Picture a toy box. The AI can't see inside it. So you tape a list to the
outside:

```text
Inside this box:
  🎲 1 dice          — for when you need real randomness
  🍪 1 cookie jar    — for counting cookies
  🔐 1 decoder ring  — for secret messages
```

The AI reads the list, points at one, and says *"use that one, please, with
these settings."* You reach in, use it, and hand back the result.

**MCP is the agreed-upon shape of that message.** That is the whole thing. The
rest is details.

<Callout type="lesson">
  The AI never sees inside your box. It reads a list of what's in there,
  picks one, and gets a result back. How the thing works — a database, an API,
  a variable in memory — is entirely your business.
</Callout>

## Why a *standard* is the load-bearing word

"Protocol" sounds like the boring part. It is the entire value.

Before MCP, connecting 10 AI apps to 10 services meant writing **100** custom
integrations — every app against every service, each one bespoke, each one
breaking on its own schedule.

With MCP it is **10 + 10 = 20**. Each app learns MCP once. Each service speaks
MCP once. Everything plugs into everything.

## Three words you need, defined plainly

These get used interchangeably everywhere and they are not interchangeable.
The distinction is the spine of this whole course, because **projects #1 and
#2 are these two things**, and everything after is a consequence.

| Word | What it is | In this course |
|---|---|---|
| **Server** | Offers tools. Waits. Never initiates. | Project #1 builds one |
| **Client** | Speaks to exactly one server. | Hand-written, ~200 lines of `fetch` |
| **Host** | Owns the conversation with the model, wrangles *several* servers, runs the loop. | Project #2 builds one |

Every AI product you admire — Claude Code, Cursor, ChatGPT with plugins — is a
variation on that third box.

Notice what the model is *not* connected to. It never reaches a server. It

is where projects #3, #4 and #5 all live.

## Six ordinary HTTP POSTs

There is no magic in here. A whole MCP conversation is six messages carrying
JSON.

| # | What happens | The actual message |
|---|---|---|
| 1 | **The AI knocks.** Which version do you speak? | `initialize` |
| 2 | **The AI reads the list.** Every tool's name, description and inputs. | `tools/list` |
| 3 | **You ask for something.** "Roll me three d20s." | *(plain English, no MCP yet)* |
| 4 | **The AI points at a toy.** It matched your sentence to a description. | `tools/call` |
| 5 | **Your code runs.** On your server, with your data. | *(just JavaScript)* |
| 6 | **The answer comes home.** | *(the response)* |

And every one of them is wrapped in a boring envelope called JSON-RPC 2.0:

```json
{ "jsonrpc": "2.0", "id": 1, "method": "tools/call",
  "params": { "name": "roll_dice", "arguments": { "sides": 20, "times": 3 } } }
```

That's it. That's the protocol you were nervous about.

## What a server can offer

Almost everybody only ever builds **tools**. There are five capabilities, and
the other four matter because they answer a question tools can't: *who gets to
decide?*

| Capability | What it is | Who decides |
|---|---|---|
| 🔧 **tools** | A verb. Something to **do**. | the **model** |
| 📄 **resources** | A noun. Something to **read**, addressed by URI. | the **host** |
| 💬 **prompts** | A saved fill-in-the-blank instruction. | the **human** |
| 🧠 **sampling** | The server asks **your host** to run a model call. | the **server** asks; the host decides |
| 🙋 **elicitation** | The server asks **your user** a question. | the **server** asks; the user answers |

<Callout type="insight" title="A number worth carrying into the next four sections">
  Four projects into a series named after this protocol, **only `tools` had
  ever been used.** The other four all arrive at once, in project #5. The
  reason that is interesting is on the next page.
</Callout>
